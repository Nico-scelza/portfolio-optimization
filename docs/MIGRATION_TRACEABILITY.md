## Breaking Changes & Migration Notes (Audit Remediation AUD-01..AUD-15 & Re-Audit AUD-04, NEW-01..NEW-04)

1. **`InstrumentConfig.currency` default changed from `"USD"` to `None` (`AUD-01`)**: omit `currency` to auto-detect quote currency and subunit scaling (`GBp`/`GBX`/`ARS`/`EUR`) from market data providers. Supply `currency` only as an explicit economic/quote override; material mismatches against provider metadata raise `FXConversionError`.
2. **Individual fixed-income valuation & rebalancing unit contract (`AUD-02`, `AUD-09`, `AUD-15.4`, `NEW-01`)**: `BrokerPosition.quantity`, `ProposedOrder.quantity`, `min_nominal`, and `lot_size` are defined in **original nominal units (1 VN original)** for individual debt (`sovereign_bond`, `corporate_bond_on`, `tbill`) and shares/units for all other instruments. `price_convention="per_unit"` denotes price per 1 bond unit of `reference_nominal`. A single centralized tradable market-price resolver (`IOL -> manual_price_usd -> unadjusted yfinance Close (auto_adjust=False) / market_price override`) feeds `fixed_income_metrics`, `latest_prices_usd`, `execution_prices_usd_per_unit`, and `rebalancing` identically. Series marked `historical_price_series_type="adjusted_total_return"`, missing unadjusted `yfinance` closes (no fallback to `auto_adjust=True`), and risk proxies remain usable for covariance risk estimation when valid, but are never published as tradable prices and block rebalancing with `RebalancingResult.status="missing_tradable_market_price"`, `feasible=False`, and `unpriced_instruments` (plus full audit metadata in `quotes_and_data_quality["price_resolution"]`).
3. **Multi-broker cash segregation & transaction-cost attribution (`AUD-03`, `AUD-11`, `NEW-02`)**: non-zero scalar `RebalancingConfig.available_cash_usd` / `cash_flow_usd` are rejected when multiple brokers are configured; migrate multi-broker calls to `available_cash_by_broker` and `cash_flow_by_broker`. `RebalancingResult` separates `initial_holdings_value_usd`, `initial_portfolio_value_usd` (pre-flow), `deployable_capital_usd` (post-flow), and per-broker `broker_ledgers` / `ending_cash_by_broker`. Each broker ledger causally decomposes unexecuted buy gross into `unfunded_buy_shortfall_usd` (true pre-cost funding deficit or broker unable to afford minimum order/fixed fee), `cost_adjusted_buy_reduction_usd` (broker's own commission/spread friction), `threshold_omitted_buy_usd` (`min_notional_usd` omissions), and `lot_rounding_residual_usd`, so fully funded rebalances with fees report `status="ok"`, `feasible=True`, and `unfunded_buy_shortfall_usd=0.0`.
4. **W-FRI cutoff semantics, tz-aware midnight handling & FX/yfinance timezone preservation (`AUD-04`, `NEW-04`)**: `as_of_cutoff` distinguishes input semantics *before* timezone normalization. Pure `datetime.date`, ISO `YYYY-MM-DD`, and legacy naive midnight `pd.Timestamp` retain end-of-day (`23:59:59.999999999`) semantics (note the inherent ambiguity of naive midnight; callers needing an explicit `00:00:00` instant must pass a tz-aware timestamp or explicit time string). ANY tz-aware timestamp/datetime/ISO string (including local midnight like `2025-07-04 00:00:00 America/New_York` / `2025-07-04 04:00:00Z` EDT / `2025-01-10 05:00:00Z` EST) or timestamp with sub-day/microsecond/nanosecond components is evaluated strictly as an exact DST-aware instant in `weekly_cutoff_tz` against `weekly_cutoff_hour`. `convert_price_series_to_usd` now accepts `target_tz` and preserves `datetime64[ns, UTC]` for tz-aware inputs when `target_tz=None` (using exact UTC instant alignment when both prices and FX are tz-aware to avoid DST fall-back ambiguity), `_download_prices` / `fetch_vix_history` preserve exact exchange trading dates for `yfinance` daily exchange-midnight bars while keeping intraday tz-aware timestamps intact, and `analyze_portfolio` forwards `target_tz=cfg.risk.weekly_cutoff_tz` consistently across downloads and mixed overrides.
5. **IOL implicit MEP timestamp policy (`AUD-06`)**: `IOLConfig.allow_mep_without_market_timestamp` defaults to `False` (conservative block when `AL30`/`AL30D` lack `market_timestamp`, e.g. static 13-column HTML). Opt in explicitly with `IOLConfig(allow_mep_without_market_timestamp=True)` to accept unverified simultaneity risk; independent `D` and `C` species are unaffected.
6. **Retired decorative parameters (`AUD-07`)**: `OptimizationConfig.simulation_samples` and `OptimizationConfig.random_seed` were removed (rejected by `OptimizationConfig.from_dict`); `DCFViewConfig.horizon_years` now defaults to `None` (inheriting `BlackLittermanConfig.default_dcf_horizon_years`).
7. **Optimizer convergence & Max Sharpe policies (`AUD-05`, `NEW-03`)**: non-convergent solver runs (`res.success=False`) report `converged=False, status="non_converged"` and are skipped as active rebalancing targets. `OptimizationConfig.non_positive_excess_return_policy` defaults to `"block"` (opt-in `"allow_with_warning"`). Both `n == 1` and `n >= 2` share the exact `1e-12` non-positive excess tolerance: `"allow_with_warning"` returns `status="suboptimal_non_positive_excess"`, explicit warnings, and `diagnostics["is_valid_target"]=False`, and `analyze_portfolio` skips rebalancing (`status="skipped_invalid_strategy_target"`) for all strategies with `is_valid_target=False`.
8. **Other v0.1.0 -> v0.2.0 API deltas**: `analytics.calcular_mcr_y_contribucion` was superseded by `compute_risk_contributions` and `analizar_contribucion_marginal_riesgo`; `stress_test_systemic` migrated from `max_daily_loss_99` to `max_weekly_loss_99` matching weekly `W-FRI` scale; default risk-free fallback rate is `0.04` (editable via `BlackLittermanConfig.default_rf_rate` / `rf_rate`).
